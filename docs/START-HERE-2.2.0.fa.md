## ۲. پیش‌نیازهای واقعی

برای مسیر نصاب از Ubuntu 22.04 یا 24.04 با systemd و دسترسی sudo استفاده کنید. دامنه و DNS در اختیار شما باشد. برای ایمیل محلی، IP عمومی، امکان تنظیم PTR از شرکت سرور، دسترسی پورت‌های لازم و فضای جدا برای نامه‌ها لازم است. با اسکن محلی فایل‌ها و بدون ایمیل‌سرور حداقل ۶ GiB RAM و ۱۵ GiB فضای آزاد اولیه در نظر بگیرید. نصب همراه ایمیل دامنه با `--with-mail-server` حداقل ۸ GiB RAM لازم دارد. ظرفیت نامه‌ها، رسانه و بکاپ جدا به این مقدار افزوده می‌شود.

قبل از شروع، مشخص کنید ایمیل دامنه را روی همین سرور می‌خواهید یا صندوق‌های فعلی باید در ارائه‌دهندهٔ قبلی بمانند. برای حالت اول `--with-mail-server` و برای دومی `--without-mail-server` را انتخاب کنید. نصب نرم‌افزار ایمیل، جای DNS و اعتبار IP را نمی‌گیرد.

## ۳. بررسی و استخراج فایل

فایل ZIP و فایل checksum را کنار هم در سرور قرار دهید. از همان پوشه اجرا کنید:

```bash
sha256sum -c idealmakoo-production-2.2.0.zip.sha256
unzip idealmakoo-production-2.2.0.zip
cd idealmakoo-production-2.2.0
```

خروجی checksum باید `OK` باشد. در صورت اختلاف، فایل را دوباره منتقل کنید و نصب را ادامه ندهید. در پوشهٔ استخراج‌شده، `RELEASE-MANIFEST.json` و `SHA256SUMS` هویت فایل‌های بسته را ثبت می‌کنند. اگر unzip نصب نیست، ابتدا بستهٔ رسمی آن را با `sudo apt-get install unzip` نصب کنید.

## ۴. ساخت تنظیمات خصوصی

```bash
sudo install -m 600 .env.example /root/idealmakoo.env
sudo nano /root/idealmakoo.env
```

مقادیر زیر را با اطلاعات واقعی عوض کنید؛ عبارت‌های نمونه را به‌عنوان دامنه یا کلید واقعی نگه ندارید:

| کلید | مقدار موردنیاز |
| --- | --- |
| `SITE_URL` و `NEXT_PUBLIC_SITE_URL` | نشانی نهایی HTTPS یکسان، مانند `https://example.com` |
| `SITE_ADDRESS` | دامنهٔ سایت بدون مسیر |
| `ACME_EMAIL` | ایمیل در دسترس برای گواهی TLS؛ می‌تواند بیرون دامنهٔ تازه باشد |
| `BOOTSTRAP_ADMIN_EMAIL` و `BOOTSTRAP_ADMIN_NAME` | هویت مالک اولیه |
| `STAFF_PROVISIONING_MODE` | حالت پیشنهادی `hybrid` برای ساخت اولیه و مدیریت بعدی از پنل |
| `MAIL_DOMAIN` | دامنهٔ صندوق‌ها، مانند `example.com` |
| `MAIL_HOSTNAME` | نام مستقل سرور ایمیل، مانند `mail.example.com` |
| `MAIL_PUBLIC_IP` | IP عمومی واقعی سرور ایمیل |
| `NOTIFICATIONS_MODE` | ابتدا `disabled`؛ پس از تکمیل سرویس‌ها و آزمون کنترل‌شده `live` |

کلیدهای داخلی خالی و رمز مالک در نصب اول تولید می‌شوند؛ کلید سرویس خارجی از پنل همان ارائه‌دهنده دریافت می‌شود. فایل env را با `source` اجرا نکنید، در گفتگو یا مخزن عمومی نفرستید و از فایل خصوصی یک کپی امن نگه دارید. در nano با Ctrl+O و Enter ذخیره کنید و با Ctrl+X خارج شوید.

## ۵. پیش‌بررسی و نصب همراه ایمیل دامنه

```bash
sudo bash scripts/preflight.sh --env-file /root/idealmakoo.env
sudo bash scripts/install-ubuntu.sh \
  --env-file /root/idealmakoo.env \
  --domain example.com \
  --email your-existing-email@example.net \
  --app-dir /var/www/idealmakoo \
  --project-name idealmakoo \
  --with-mail-server
```

دامنه و ایمیل بالا نمونه‌اند؛ آن‌ها را عوض کنید. اگر صندوق ایمیل فعلی دارید، گزینهٔ آخر را `--without-mail-server` بگذارید و SMTP فعلی را طبق راهنمای سرویس‌ها تنظیم کنید. نصاب خطای ساخت، migration، مجوز و اعتبارسنجی را نادیده نمی‌گیرد. فقط خطای گذرای دریافت در محدودهٔ مشخص دوباره امتحان می‌شود.

در نصب ایمیل، اگر نصاب برای DNS توقف کرد، فایل عمومی `/var/www/idealmakoo/mail-server/dns-records.json` را بخوانید و رکوردها را طبق بخش ۶ راهنمای سرویس‌ها ثبت کنید. SPF را به شکل یک رکورد معتبر ترکیب کنید، DKIM را عین مقدار تولیدشده بگذارید، DMARC را با پایش شروع کنید و PTR را از شرکت سرور بخواهید. سپس همان فرمان نصب را دوباره اجرا کنید. نصاب از توقف واقعی عبور نمی‌کند و تنظیمات ساخته‌شده را حفظ می‌کند.

بعد از نصب، فایل مرجع تنظیمات `/var/www/idealmakoo/shared/.env` است. تغییر فایل اولیهٔ `/root/idealmakoo.env` به‌تنهایی تنظیمات نصب موجود را عوض نمی‌کند. فرمان‌های بررسی:

```bash
sudo bash /var/www/idealmakoo/current/scripts/check-health.sh 240
sudo bash /var/www/idealmakoo/current/scripts/doctor.sh
```

اگر خطا باقی است، مرحله و پیام خطا را با جدول عیب‌یابی راهنمای سرویس‌ها تطبیق دهید. برای رفع خطا TLS را خاموش نکنید، checksum را تغییر ندهید و دیتابیس را حذف نکنید. مسیر proxy مجاز و imageهای ازپیش‌دریافت‌شده توضیح داده شده‌اند؛ حالت local-images به معنی بی‌نیازی کامل از اینترنت نیست.

## ۶. ورود مالک و ساخت تیم

در `/fa/auth/login/` با ایمیل مالک و رمز موجود در فایل خصوصی نصب وارد شوید. MFA را در بخش امنیت فعال کنید و کدهای بازیابی را در محل امن جدا نگه دارید. از `/fa/admin/staff/` حساب‌های واقعی تیم، نقش، زبان‌های مجاز و مجوزهای CRM را تعیین کنید. نویسنده و بازبین باید مستقل باشند؛ بازبینی محتوای خود مجاز نیست.

هر کارمند ابتدا راهنمای نقش خودش را از بخش کمک یا `/manuals/index.html` بخواند. این آموزش‌ها شامل وظایف، مسیرهای پنل، مراحل یک کار کامل، تصاویر واقعی با حساب آموزشی، خطاها و نحوهٔ تحویل کار هستند. نام نقش به‌تنهایی دسترسی به همهٔ مشتریان یا اطلاعات مالی نمی‌دهد؛ محدوده و مجوزهای جدا هم اعمال می‌شوند.

## ۷. فعال‌سازی کانال‌ها

| سرویس | کار عملی |
| --- | --- |
| پیامک مشتری | حساب و اعتبار کاوه‌نگار، API key و قالب تأییدشدهٔ OTP را تهیه کنید؛ `KAVENEGAR_API_KEY` و `KAVENEGAR_OTP_TEMPLATE` را تنظیم کنید. `CUSTOMER_SMS_OTP_ENABLED=true` باشد. |
| ایمیل | ایمیل محلی را کامل کنید یا `SMTP_HOST/PORT/USER/PASSWORD/FROM` را از سرویس فعلی بگیرید. وضعیت TLS و DNS را بررسی کنید. |
| تلگرام | bot را از BotFather بسازید، token و username را تنظیم کنید، bot را با مجوز ارسال به کانال اضافه کنید و کانال عمومی را جدا از اتصال شخصی کارکنان تنظیم کنید. |
| AI | provider و مدل پشتیبانی‌شده و کلید واقعی را تنظیم کنید؛ بودجه و سقف‌ها را تعیین کنید. استفادهٔ دستیار با اقدام صریح نقش مجاز انجام می‌شود. |

دستورها و تصویر ذهنی هر مرحله در راهنمای سرویس‌ها آمده است. پس از تکمیل تنظیمات، ارسال را در حالت `live` و با مقصد متعلق به خودتان بررسی کنید. دریافت موفق یک کانال، موفقیت کانال‌های دیگر را ثابت نمی‌کند. کارکنان باید کانال شخصی‌شان را تأیید کنند و مجوز پرونده را داشته باشند. انتشار عمومی برای مشترکانِ همان موضوع و زبان و کانال انجام می‌شود؛ موضوع تازهٔ «محتوا» به‌صورت پیش‌فرض فعال نیست و رضایت مستقل می‌خواهد.

## ۸. آزمون پذیرش توسط مالک

۱. با مشتری آموزشی و موبایل تحت اختیار خود، دریافت کد و ورود را امتحان کنید. کد اشتباه باید رد شود و کد استفاده‌شده دوباره پذیرفته نشود.

۲. یک استعلام محصول بسازید؛ شمارهٔ پیگیری، نمایش در حساب مشتری، پروندهٔ کارمند مجاز و اعلان کانال‌های تأییدشده را بررسی کنید. ایمیل برای مشتری دارای موبایل تأییدشده اجباری نیست.

۳. یک محتوای آموزشی را ذخیره، با همکار مستقل بازبینی و با ناشر منتشر کنید. عنوان، دسته، برچسب، تصویر، لینک و زبان را در صفحه و جست‌وجو ببینید.

۴. نظر مشتری را ثبت کنید. پیش از تأیید نباید عمومی شود. ناشر یا مدیر مجاز آن را بررسی کند؛ امکان رد نظر تأییدشده نیز در صف وضعیت مربوط وجود دارد.

۵. گزارش بازدید و تعامل و مصرف سرویس را با نقش مجاز باز کنید. هزینهٔ نامعلوم را صفر نخوانید و ریال و دلار را با هم جمع نکنید.

۶. `/sitemap.xml` را باز کنید. فایل ریشه فهرست سایت‌مپ‌های زبان و نوع محتواست. یکی از فایل‌های زیرمجموعه را نیز باز و لینک عمومی را بررسی کنید.

۷. مالکیت دامنه را در Google Search Console و Bing Webmaster Tools با DNS ثابت کنید و `/sitemap.xml` را ثبت کنید. راهنمای Yandex هم همراه است. پذیرش سایت‌مپ یا پاسخ موفق ابزارها، تضمین ایندکس یا رتبه نیست.

۸. یک بکاپ رمزنگاری‌شده تهیه و در محیط جدا تمرین بازیابی کنید. کلید رمزگشایی و کلیدهای حریم خصوصی را طبق راهنما جدا نگه دارید. بکاپ بدون امکان بازیابی بررسی‌شده کافی نیست.

## ۹. ارتقای نصب موجود

فایل env فعلی، کلیدها، رسانه و ledger را حفظ کنید. نسخهٔ تازه را در پوشهٔ جدا استخراج کنید و از release فعلی اجرا کنید:

```bash
sudo bash /var/www/idealmakoo/current/scripts/update.sh \
  --source /ABSOLUTE/PATH/idealmakoo-production-2.2.0
```

نسخهٔ ۲٫۲ دو migration افزایشی `043_customer_engagement.sql` و `044_resource_notifications.sql` را اضافه می‌کند. ۴۱ migration بستهٔ ۲٫۱٫۴ و شماره‌های قبلی تغییر نکرده‌اند؛ شمارهٔ 005 از ابتدا در مجموعه نبوده است. در ناسازگاری checksum، ارتقا باید برای بررسی متوقف شود. این بسته به معنی اجرای ارتقا روی دیتابیس نصب‌شدهٔ شما نیست.

فعال‌کردن ایمیل محلی برای نصب قدیمی یا انتقال صندوق از سرویس دیگر را طبق راهنمای ایمیل انجام دهید؛ تغییر MX به‌تنهایی نامه‌های قبلی را منتقل نمی‌کند. بکاپ format4 اطلاعات ایمیل محلی را هم دربر می‌گیرد و سازگاری format3 طبق قواعد اعتبارسنجی حفظ شده است.

## ۱۰. حدود روشن تحویل

کد روی محیط پذیرش جدا ساخته و اجرا شده است؛ دامنه، SSH، DNS و کلیدهای واقعی شما در این گفتگو ارائه نشده‌اند. بنابراین نصب روی سرور شما و ارسال واقعی به مشتریان انجام نشده است. تماس تلفنی خارج سایت فقط با ثبت دستی در CRM یا اتصال سرویس تلفنی به ورودی امضاشده وارد گردش می‌شود. نظرها در این نسخه تخت‌اند و پاسخ تودرتو ندارند. اتصال اختیاری IndexNow به‌صورت داخلی پیاده نشده؛ مسیر استاندارد سایت‌مپ و کنسول‌های جست‌وجو مستند شده است.

برای نسخهٔ دقیق هر آزمون، محدودیت محیط و موارد وابسته به سرویس واقعی، گزارش پذیرش همراه را بخوانید. گزارش‌های تاریخی و تصاویر قدیمی، نتیجهٔ اجرای جدید معرفی نشده‌اند.
