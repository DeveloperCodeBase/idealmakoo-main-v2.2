# پذیرش عملیاتی ۲٫۱٫۳ — نصب، بکاپ، بازیابی و ارتقای C2

**نصب خالی، بکاپ داده‌دار و دانلود، بازیابی روی Ubuntu مستقل و سپس ارتقای همان نصب بازیابی‌شده به C2 موفق‌اند.** تطبیق مستقل runtime و هر ۱۹ کنترل API پس از ارتقا نیز با خروج صفر کامل شده‌اند. زمان‌های شواهد UTC هستند.

سورس جاری C3 پس از این سناریو، فقط دو فایل نمایشیِ بارگذاری منابع و یک آزمون موجود را تغییر داده است. [تطبیق مستقل](verification-evidence/repair-2.1.3/candidate03-source-delta.safe.json)، برابری تمام بک‌اند، API، worker، عملیات، migrationها و وابستگی‌ها با C2 را ثبت می‌کند. C3 ساخت و بررسی مرورگر متمرکز مستقل دارد؛ نصب/ارتقای Ubuntu و بکاپ/بازیابی برای C3 دوباره اجرا نشده‌اند. این گزارش به همان بسته‌های C1 و C2 با hashهای زیر تعلق دارد.

نتایج نصب خالی، بکاپ و بازیابی در بخش‌های نخست به `candidate-01` با SHA-256 زیر تعلق دارند؛ نتیجهٔ ارتقای C2 در بخش پایانی، با hash مستقل آن بسته ثبت شده است:

```text
2deb94d17e0852d75102461fa566555c973f632320729a366a73b86ae9381574
```

سورس و اسکریپت‌های محصول در اجرای این سناریوها تغییر نکردند. نسخهٔ یکپارچهٔ گالری، مکث پیش‌نمایش، CSS و favicon، آرشیو مستقل C2 دارد و با فرمان اصلی ارتقا روی همان نصب بازیابی‌شده بررسی شده است. نتیجهٔ جاری کل انتشار در [گزارش پذیرش](VERIFICATION.fa.md) آمده است.

## خطاهای ابزار پذیرش که حفظ شده‌اند

آماده‌سازی نخست محیط، پیش از اجرای نصاب محصول، از یک API هش مخصوص Python 3.11 روی Python 3.10 استفاده می‌کرد. ابزار پذیرش به هش‌کردن جریانیِ سازگار تغییر کرد؛ اسکریپت محصول تغییری نکرد.

نخستین سناریوی API نیز در اولین GET ناشناس با پاسخ خالیِ نشانی داخلی proxy متوقف شد. بازخوانی مستقل نشان داد هنوز فقط مالک اولیه وجود دارد و نشست، challenge، MFA، ورود ناموفق و ثبت رویداد ورود ایجاد نشده‌اند. همان driver با نشانی واقعی سایت در شبکهٔ میزبانِ ماشین آزمایشی اجرا شد و ۱۲ کنترل را گذراند. دادهٔ حسابی reset نشد و برنامه یا کنترل امنیتی proxy تغییر نکرد. خروج ناموفق اولیه در شواهد باقی است.

## محیط و حدود این نتیجه

این نصب روی **Ubuntu 22.04.5، چهار vCPU و ۶ GiB حافظه در QEMU/TCG بدون KVM** انجام شد. برای این محیط کندِ شبیه‌سازی، تنظیم مستند timeout برنامه و worker روی ۹۰ ثانیه و start period روی ۶۰۰ ثانیه بود. پیش‌فرض محصول تغییر نکرد و کنترل حداقل منابع دور زده نشد. مدت اجرای این ماشین، معیار سرعت یک سرور واقعی یا مرورگر کاربران نیست.

مسیر وب آزمایش HTTP روی loopback است؛ ACME/TLS عمومی، دامنهٔ واقعی کاربر، ارسال ایمیل/SMS واقعی و تولید پولی AI در این سناریو اجرا نشده‌اند. تأیید TLS بالادست و امضای APT فعال مانده‌اند. داده‌ها فقط fixtureهای مصنوعیِ همین آزمون هستند. restore یا drill روی همان میزبان در این نوبت تکرار نشده است.

در میزبان تازه، دسترسی کارکنان از آرشیو می‌آید و حذف‌های جدید از دفتر مستقل اعمال می‌شوند؛ این رفتار با نگه‌داری وضعیت امنیتی جاری در restore همان میزبان یکسان نیست. حدود و فرمان‌ها در [امنیت بازیابی](RESTORE-SECURITY.fa.md) و [راهنمای بکاپ/restore](BACKUP-RESTORE.fa.md) توضیح داده شده‌اند.

## ارتقای همان نصب به سورس نهایی C2

دیسک همان میزبان بازیابی‌شده، بدون ساخت clone جدید یا بازنشانی داده‌ها، دوباره راه‌اندازی شد. فرمان `update.sh` از release نصب‌شده، دقیقاً یک بار با مسیر سورس C2 اجرا شد. بستهٔ ورودی همان ZIP ارائه‌شده با SHA-256 زیر بود:

```text
05f9fada3a33e7df149012e0eeae0824e9fb3dda93b4387a70278626dd767578
```

هر ۳۵۳۵ فایل سورس بسته و ۷۵ فایل حساس عملیات و migration، شامل Dockerfile و Compose، پیش از اجرا تطبیق داده شدند. اسکریپت اصلی، کنترل منابع، آنتی‌ویروس کامل و هر دو بکاپ اجباری حفظ شدند. تنظیمات مستندِ محیط TCG همان ۹۰ ثانیه برای health timeout و ۶۰۰ ثانیه برای start period بود؛ پیش‌فرض محصول تغییر نکرد.

شناسهٔ image واقعی برنامه و worker:

اعتبارسنجی دو بکاپ جدید در این چرخه شامل پایان موفق اسکریپت اصلی، دو فایل عادیِ رمزنگاری‌شده با age و بازگشت عادی سرویس‌هاست؛ این دو آرشیو جداگانه خارج از میزبان رمزگشایی نشده‌اند. آزمون رمزگشایی مستقل و بازیابی واقعیِ بکاپ داده‌دار در بخش‌های قبلی با آرشیو C1 انجام شده است. به این نتیجه، restore یا drill دیگری روی همان میزبان، TLS عمومی یا تحویل واقعی سرویس‌های خارجی نسبت داده نمی‌شود.

یک خطای read-only ابزار پیش از شروع ماشین نیز محفوظ است: hashِ manifest کنار ZIP به‌اشتباه با manifest داخلی مقایسه شده بود. manifest بیرونی دو فیلد مشخصات آرشیو اضافه دارد؛ پس از تطبیق همان دو فیلد و برابری باقی بدنه، بررسی درست کامل شد. این خطا پیش از اجرا یا staging محصول رخ داد و به تغییر محصول یا ابزار چرخهٔ اجرا منجر نشد.
