# برنامهٔ اجرای اصلاحات ۲٫۱٫۱

این برنامه برای ادامهٔ اصلاح همان پروژه است. فایل ارسالی ۲٫۰٫۰ و نسخهٔ ذخیره‌شدهٔ ۲٫۱٫۰ هر دو با checksum بررسی شدند؛ مبنای توسعه، نسخهٔ جدیدتر است تا اصلاحات کاربران، ذخیره‌سازی و بازیابی حذف نشوند. گزارش‌های قدیمیِ داخل پروژه سابقهٔ همان نسخه‌ها هستند و نتیجهٔ اجرای نسخهٔ ۲٫۱٫۱ محسوب نمی‌شوند.

## ثبت وضعیت فعلی

Build03 با شناسهٔ `i2FywRVMQcWLcBXtSt9h7`، ۸۰۴ ورودی ثابت، TypeScript و ۸۱۰ آزمون واحد موفق ثبت شده است. اسکن هشت الگوی اعتبارنامه روی ۲۱۶ فایل مرورگرِ همین build صفر یافته داشته است. این بررسی، مقایسه با مقادیر محرمانهٔ واقعی نیست.

اجرای کامل ۵۶ آزمون مرورگر، ۵۲۸ PostgreSQL و ۲۰ API با زمان و محدودهٔ پیشین حفظ می‌شود. اجرای منتخب build02 نتیجهٔ ۱۷/۲۰ داشت؛ پس از اصلاح دو فایل نشانگر fallback و CSS، فقط همان سه مسیر ناموفق روی build03 دوباره اجرا شدند و هر سه موفق‌اند. این زنجیره با اجرای کامل تازه اشتباه گرفته نمی‌شود. آزمایش واقعی ارتقای schema نتیجهٔ ۳۷/۴/۰ داشته است. Lighthouse و نصب Docker/بکاپ/بازیابی هنوز برای تکمیل پذیرش در انتظار شاهد واقعی‌اند.

## تصمیم‌های اجرایی

- قالب و دارایی‌های بصری اصلی حفظ می‌شوند. تغییر معنای عنوان‌ها برای دسترس‌پذیری با حفظ اندازه و سبک انجام می‌شود.
- حالت `hybrid` ایجاد اولیهٔ کارکنان از env و مدیریت بعدی از پنل را پوشش می‌دهد. حالت محدودتر `env` انتخاب اپراتور است. ثبت‌نام عمومی فقط حساب مشتری می‌سازد.
- کلید سرویس‌های بیرونی و اسرار فقط در تنظیمات خصوصی سرور قرار می‌گیرند. آزمون mock یا بررسی شکل درخواست به‌عنوان ارسال موفق به ارائه‌دهنده معرفی نمی‌شود.
- محتوای هر زبان، بازبینی و وضعیت انتشار مستقل دارد. خروجی AI پیش‌نویس قابل ویرایش است و انتشار عمومی نیازمند اختیار مناسب است.
- نتیجهٔ ناموفق و اجرای قطع‌شده نگه داشته می‌شود. اجرای مجدد، نتیجهٔ قبلی را حذف یا به موفقیت تبدیل نمی‌کند.
- معیار تحویل، رفتار اجراشده و شواهد قابل بررسی است. رتبهٔ گوگل، امتیاز یکسان روی همهٔ سخت‌افزارها و نبود هر خطای احتمالی قابل تضمین نیست.

وضعیت نهایی و محدودیت‌های باقی‌مانده در [گزارش پذیرش](VERIFICATION.fa.md) ثبت می‌شود؛ این برنامه به‌تنهایی ادعای تکمیل مراحل نیست.
